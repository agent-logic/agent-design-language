# Issue #294 Initialized Design Envelope Recovery

## Goal

Add one typed, CAS-guarded operation that repairs an initialized, unbound issue's design envelope without rewriting history. The operation relocates authored design and diagram artifacts to safe repository-owned paths and canonicalizes independently proven reviewer identity.

## State transition

- Input phase must be `initialized` with `branch` and `worktree` absent.
- Request carries expected generation and digest, old/new artifact paths, expected old artifact digests, reviewed generation/digest, and structural prior-review provenance: canonical projectless session UUID, reviewer turn UUID, spawned task identity, `thread_source: subagent`, and `fork_turns: none`. The operation validates canonical UUID shape and complete internally consistent provenance, records it in append-only audit, but never treats it as sufficient authority to preserve approval. Recovery always sets design review to pending, so a normal new canonical fresh-session review and typed design approval is mandatory before bind. This avoids a new registry, signer, or caller-asserted approval authority while satisfying the requirement to reject unbacked noncanonical identity correction.
- Validate all request evidence and both destination paths before any mutation.
- First persist and fsync a `prepared` recovery journal containing the pre-state CAS, intended post-state digest inputs, source/destination identities and digests, deterministic temporary names, and destination-absence facts. The journal authority is the repository's discovered Git common directory, obtained through the same typed Git-topology resolver used for shared request paths—not by literal `<worktree>/.git` traversal. Recovery opens and pins the canonical common-directory descriptor, verifies it belongs to the current repository/worktree topology, then creates/replaces append-only attempt receipts under `csdlc-v2/recovery-journals/<issue>/<attempt>/` with no-follow ancestor checks, identity revalidation before every journal write, and file/parent fsync ordering. This works when a linked worktree's `.git` is a gitfile and fails closed on topology or ancestor drift. All source reads, temporary creates, and destination installs likewise use descriptor-relative anchored traversal with no-follow semantics from an opened canonical repository root; every ancestor and target identity is revalidated immediately before each operation, and platforms lacking the required primitives fail closed. Recovery creates exclusive staged files beside each destination, fsyncs each file and parent, installs the destination with no-replace hardlink semantics, retains the stage as the ownership witness until the installed identity is durably journaled, then removes owned stage/delete quarantines only when the journaled inode identity and digest still match. Advance the attempt ledger after each installed artifact and before the issue-directory transaction, then commit the issue-directory transaction as the sole authority commit point. On restart, recovery first loads canonical issue state: if it matches the journal's intended post-generation, paths, digests, and audit event, the commit is authoritative regardless of a stale journal marker and cleanup preserves both canonical destinations; only a record still matching the pre-state CAS permits rollback of identity/digest-matching staged destinations or owned-delete quarantines. Any other combination fails reconciliation without deletion. The focused proof covers the declared deterministic recovery failpoints, stage/owned-delete cleanup, source/path safety classes, and a linked-worktree bind-before/after fixture that reproduces the #292-style `.git` authored-path `unsafe_checkout` before recovery and successful bind after relocation, fresh approval, and ready transition.
- Preserve initialized/unbound topology.
- Unconditionally set design review to pending. Recovery never preserves or rewrites approval; only a subsequent normal fresh-session design review and typed approval can restore it.

## Path safety

Bootstrap and recovery reject absolute paths, parent traversal, `.git` or `.git/...`, issue control paths, and paths with symlink or non-directory ancestors. Safe authored artifacts live outside Git control and lifecycle state paths, such as `docs/...` or `.csdlc/prepared/...` during pre-bind preparation. Design and diagram destinations must be distinct from each other and from both source paths; source/destination aliasing, hard-link identity aliasing, and cross-swaps are rejected before journaling. Recovery destinations must be absent; existing destinations, even byte-identical ones, fail closed to avoid ambiguous ownership. The old unsafe sources are retained as immutable historical inputs; only canonical authority is relocated. Temporary or destination files created by an interrupted pre-commit attempt are removed only when journaled identity and digest still match, so unrelated files are never overwritten or deleted.

## Audit and failure semantics

The recovery audit is append-only and records old/new reviewer identity, design/diagram paths and digests, reviewed generation/digest, reviewer thread/session UUID, no-inheritance evidence, approval disposition, actor, generation, and pre/post state digests. Wrong phase, stale CAS, absent/drifted source artifacts, unsafe destinations, insufficient reviewer proof, or attempted history replacement fails before mutation.

## Validation

Focused Rust tests cover structural projectless reviewer provenance plus mandatory approval invalidation, atomic relocation, CAS failures, path and alias classes, audit completeness, phase rejection, bootstrap rejection, crash/restart recovery at every journal/file/state boundary, destination collision behavior, and a linked-worktree fixture reproducing the #292 `unsafe_checkout` failure before recovery and successful bind after recovery. A local dependency-gate fixture proves #292 stays blocked without terminal/ancestral #294 evidence. Live AC-10 proof is deliberately deferred to closeout: `csdlc-finish` supplies #294 terminal receipt and observed SHA, typed issue read confirms live terminal state, and read-only Git ancestry checks that SHA against current `origin/main`; #292 may resume only when all agree.

## Non-goals

No #292 mutation or product implementation; no generic lifecycle rewrite; no merge or closeout authority.
