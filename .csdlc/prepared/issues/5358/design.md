# Issue 5358 design — C-SDLC v2 acceptance preparation

Status: design-ready preparation only; acceptance execution is not authorized.

## Decision

Prepare a typed, issue-local acceptance contract for C-SDLC v2 as one of the
early v0.91.8 acceptance lanes. This issue defines what future exact-revision
acceptance must prove, but this preparation session does not run acceptance,
change implementation, publish a PR, deploy binaries, or close the issue.

The accepted product boundary is the independent Rust v2 lifecycle control
plane under `csdlc-v2/`, resolved through the final `v1_sunset` generation
selector and installed in `.adl/bin/csdlc-v2/`. ADL and Runtime v3 are external
consumers or peer products, not implementation authority for C-SDLC v2.

## Acceptance surface

Future acceptance must bind all claims to one exact revision and prove:

1. `csdlc-install resolve`, install receipts, and the final coexistence
   inventory select only the approved v2 generation and reject forbidden live
   v1 lifecycle guidance.
2. The typed lifecycle path covers initialization, design approval, binding,
   card editing, PVF scheduling/validation, review, publication, shepherding,
   and terminal closeout/reconciliation without direct Markdown/state edits.
3. All six generated cards remain schema-valid and digest-consistent.
4. Claim ownership, protected-path collision rejection, heartbeat/recovery,
   existing-worktree binding, and terminal receipt/common-Git-dir invariants
   fail closed.
5. Publication and closeout are idempotent, exact-revision-bound, and cannot
   bypass current review, validation, checks, or issue/PR truth.
6. Operator skills and stable installed binaries agree with the generation
   selector and current root policy.
