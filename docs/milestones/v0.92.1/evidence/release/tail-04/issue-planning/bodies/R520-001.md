## Summary

Repair the P1 crash-consistency defect in dynamic-agent removal so roster, orientation, checkpoint/tombstone, and derived Runtime state cannot retain incompatible durable truths after an interrupted removal.

## Goal

Make removal of a dynamic agent recoverable and deterministic across every persistence boundary.

## Required Outcome

At exact review candidate `c24f8fa65ce445b03ce6cd69007307291d78b60c`, findings `A520-ARCH-001` and `C520-CODE-001` show that `remove_agent` can durably write a checkpoint tombstone before the reduced roster is committed. The repair must establish one authoritative lifecycle state machine and make every interruption converge after restart to either a recoverable resident agent or an authoritatively absent agent.

## Deliverables

- A durable removal transaction, intent, or equivalent recovery protocol spanning declaration, orientation, checkpoint/tombstone, and affected in-memory projections.
- Idempotent startup reconciliation for partially completed removal.
- Deterministic failure-injection tests for every persistence boundary.
- Updated Runtime continuity evidence tied to the repaired exact revision.

## Acceptance Criteria

- One durable record or explicitly defined recovery rule is authoritative for the dynamic-agent lifecycle transition.
- A failure before, during, or after each persistence step converges on reopen to a resident agent with recoverable state or an absent agent with an authoritative tombstone.
- Roster, orientation, population, session, checkpoint, and tombstone projections reconcile idempotently.
- The API never reports failed removal while leaving an unrecoverable resident identity.
- Reordering writes alone is not accepted unless failure injection proves both crash directions safe.
