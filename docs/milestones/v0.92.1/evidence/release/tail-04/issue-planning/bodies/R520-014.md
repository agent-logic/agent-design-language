## Summary

Remediate P2 finding `S520-SEC-002` from internal review #520 by requiring an independent SSH recovery path whenever the active Spot Runtime root creates a publicly addressed EC2 instance. At reviewed candidate `c24f8fa65ce445b03ce6cd69007307291d78b60c`, both the module and root default to no SSH CIDRs and no key pair while the instance receives a public IP.

## Goal

Ensure operators can recover a public Runtime node when user data, TLS, Runtime, or observability startup fails, without relying on an optional SSM path or emergency access expansion.

## Required Outcome

Terraform rejects a public Runtime configuration unless it supplies one operator-approved EC2 key pair and explicit SSH ingress CIDRs, and the documented fast path demonstrates a recoverable `/32` configuration while preserving existing hardening and application-port isolation.

## Deliverables

- Terraform validation or plan-time preconditions for public Runtime SSH recovery inputs.
- One-key-pair configuration using explicit authorized SSH CIDRs.
- Updated `infra/aws/csm-runtime-spot/terraform.tfvars.example` and fast-path README.
- Negative Terraform tests for a null key and empty SSH ingress on a public node.
- Bounded AWS proof of SSH reachability from the authorized `/32` and application-port isolation.
- Retained disposal evidence for any paid proof infrastructure.

## Acceptance Criteria

- A public Runtime configuration with `key_name = null` is rejected before apply.
- A public Runtime configuration with an empty SSH ingress list is rejected before apply.
- The documented public configuration uses exactly one operator-approved key pair and explicit ingress CIDRs.
- The documented proof uses a `/32` recovery ingress and verifies SSH reachability from that authorized address.
- Application ports remain constrained to their intended callers and are not opened by the SSH change.
- IMDSv2, encrypted storage, and existing security-group controls remain intact.
- Private-only deployment roots are not forced to expose public SSH.

## Non-goals

- Adding or managing a second key pair.
- Requiring public SSH on private-only deployment roots.
- Treating optional SSM availability as a replacement for the required SSH recovery path.
- Broadening SSH ingress beyond explicit operator-approved CIDRs.
- Redesigning unrelated network or Runtime architecture.
