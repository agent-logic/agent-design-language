# Operator Preflight For #264

This is the handoff checklist for the person doing directory submission. It is safe to give to a social media intern as long as they have only the account access you intend and understand not to paste secrets into GitHub, Slack, or repo files.

## Repo-ready inputs

- Show: `The Cognitive Stack`
- Website: `https://agent-logic.ai/podcast/`
- RSS: `https://agent-logic.ai/podcast/feed.xml`
- Contact mailbox: `podcast@agent-logic.ai`
- Category: Technology
- Explicit: false
- Owner/author: Agent Logic

## Before the intern starts

1. Decide which provider accounts the intern may access.
2. Make sure each account has 2FA and recovery owned by Agent Logic, not a personal account.
3. Give the intern mailbox access or arrange live forwarding for `podcast@agent-logic.ai`.
4. Confirm they may complete provider terms/content-rights attestations, or reserve those clicks for you.
5. Confirm whether Apple and YouTube should remain private/scheduled until you personally approve publication.

## Intern instructions

For each provider:

1. Open the provider runbook in `provider-runbooks.md`.
2. Sign in only through the official provider site.
3. Enter the RSS feed URL exactly.
4. When a verification code arrives, use it only in the provider UI and do not save it.
5. Screenshot or copy only non-secret status information after the provider flow completes.
6. Fill a ledger entry using `submission-ledger.schema.json`.
7. If the provider asks for rights, territory, monetization, paid-promotion, explicit-content, public release, subscription, or channel visibility choices not already approved, stop and ask you.

## Stop signs

Stop immediately if:

- the feed imports a title other than `The Cognitive Stack`;
- artwork, owner email, or episode count do not match the feed;
- a provider requests payment, subscription setup, advertising, monetization, or legal attestation beyond content rights;
- a provider wants a personal phone, personal email, or non-company recovery method;
- there is a duplicate existing show result that might need a claim/merge/removal path.
