# v0.93 Quality Gate

Status: first-pass contract, not qualification evidence.

## Required denominator

The execution graph defines 64 candidate outcomes. At opening, retain the accepted exact denominator, real cross-repository issue mapping and any explicitly approved changes. Runtime v4 RV-01 through RV-08 is mandatory. Launch CF-01 through CF-07 is included in this first pass. A count of closed issues cannot replace result-by-result acceptance.

## Gate sequence

1. RD-11: accept independently installed products, public ADL without private access, authentic copied-record C-SDLC recovery, demo ownership and rollback lockset.
2. RV-08: accept all required plugin adapters, generation fencing, interruption recovery, provider integration and operations on installed Runtime artifacts.
3. Feature acceptance: prove each governance/security outcome in its installed consumer, including every declared negative case. Trace and policy prose alone cannot close an implementation result.
4. CF-05 through CF-07: independent launch rehearsal, truthful website handoff, then authorized live Beta 1 launch with tester admission, end-to-end verification and rollback. Unexecuted launch blocks release.
5. QUALIFY: independently run the integrated milestone denominator against the exact cross-repository lockset, then TAIL-01 accepts or rejects release quality.

## Evidence record

Every result records source heads, installed artifact digests, contract versions, environment class, actual success/failure/recovery scenario counts, expected and observed behavior, redacted logs, skipped checks with reasons, reviewer and finding dispositions. Mock, component, retained and fresh installed proofs are labeled separately. Zero executed scenarios are not success. A changed source/artifact requires requalification of affected consumers.

## Blocking conditions

Missing Runtime v4 outcomes, lost accepted work without declared disposition, stale authority accepted, inaccessible rollback, private dependencies in public ADL, unsigned/unscoped authority, secret or private-state disclosure, missing negative cases, unsupported public claims, or unresolved actionable review findings block acceptance. A missing Beta 1 requirement blocks the predecessor; it cannot be disguised as successor scope.

## Resource and approval boundary

Local fixture proof is the default. Real providers, deployment environments and customer repositories need explicit per-issue scope, budget and access. Synthetic security demonstrations do not prove production compliance. Planning issue #1047 runs package validation only; none of the product gates has run as part of this issue.
