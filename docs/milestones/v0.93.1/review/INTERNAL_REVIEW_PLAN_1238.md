## Review lanes and execution order

Use one shared candidate packet plus annexes for changed repositories and interface-focused annexes for unchanged consumers affected by a changed producer. Each assignment names exact repository/commit/tree, inventory rows, relevant interfaces, prior review inputs, reviewer identity and independence, permitted read-only/proof actions, expected report, and stop boundary. Work can be parallel across independent changed repositories after the freeze; cross-repository conclusions wait for both ends of each affected edge. Do not stack review findings or approval onto a single repository's summary.

| Lane | Required focus |
| --- | --- |
| Code and behavior | Changed production paths in touched repositories and affected consumers, error/retry/cancellation/recovery, real installed entry points, and inert or partial behavior. |
| Tests, PVF and CI | Criterion-to-proof mapping, assertions reached, positive/negative counts, fast/slow selection, isolated build ownership, and skipped or zero-scenario cases. Reuse valid exact-candidate runs. |
| Security and privacy | Credential and policy boundaries, private/public evidence separation, provenance and authorization bound to exact bytes, redaction and safe failure. |
| Architecture and interfaces | One implementation owner per component; all consumer→producer edges, version compatibility, deployment/runtime boundaries and migration drift. |
| Dependencies and supply chain | Manifests/locks/toolchains and distributable inputs for changed repositories and affected interfaces; artifact integrity, current exact-candidate build evidence where required, and no implicit sibling source. Reuse qualifying retained builds rather than rebuilding every lockset role. |
| Documentation and claims | README/manual/release claims changed for this candidate or affected by its interfaces, v0.93.1 milestone docs, #1236 publication packet, actual website/download claims and supported versions. |
| Installed journeys and demos | Supported CodeFriend/Runtime/template journeys, actual renderer outputs (including branded formats), live CF-07 result, rollback and negative cases. Distinguish retained evidence from a new run. |
| Lifecycle and retained evidence | Native records, issue/PR mapping, review and closeout truth, old findings, artifact custody, adverse evidence, and current release-tail predecessor state. |
| Release/publication synthesis | Exact seven-role candidate, quality-gate disposition, public/private artifacts, destinations and approvals; no release action. |

Start with packet/inventory integrity, then independent specialist reports. Resolve cross-role disagreements in a recorded log; deduplicate findings without losing raw source IDs or the highest supported severity. Synthesize only after every required lane has an authored observation and coverage ledger. Apply a separate redaction/evidence audit and independent review-quality assessment to the assembled packet. Packet-quality PASS is not product or release PASS.

## Focused proof and privacy rules

Review retained exact-candidate evidence first. Run only a focused reproduction needed to settle a concrete finding or required criterion, recording command, checkout, selected tests, executed/failed/skipped counts, PVF lane, determinism, resource profile, output digest and what the result does *not* prove. Source compilation does not establish installed behavior. A successful command with zero executed scenarios is non-proving. No blanket seven-repository rebuild, duplicate child test campaign, paid provider call, cloud mutation, website deployment, binary replacement, tag or release is authorized by this plan.

At preparation readback, the RD-11 inventory names public ADL and six private repositories; this is a visibility inventory, not a claim that seven repositories changed. Recheck repository and artifact visibility at candidate freeze; classify each evidence item by its actual disclosure permission. Keep private raw logs, source excerpts, credentials, host paths, account details and restricted findings in controlled annexes owned by their repository or approved evidence store. The public ADL packet contains a redacted projection, stable evidence locators and verified digests only where disclosure is approved. A public-safe projection must still let an authorized reviewer resolve the exact private evidence; otherwise mark the criterion `not_proven`. Audit both the private packet and public projection before PR publication. Do not copy private evidence into the ADL worktree merely to make a validator pass.

## Durable output and acceptance checks

The execution packet should have a private authoritative manifest and a tracked, public-safe rollup under `docs/reviews/v0.93.1/internal-review-1238/`. The private manifest enumerates the actual changed-repository set, seven lockset role identities and their changed/unchanged classifications, upstream acceptance, affected-edge and annex locations/hashes, lane reports, raw findings, proof receipts, coverage ledgers, and its own explicit self-exclusion from hashing. The public rollup contains scope/status, safe candidate references, lane coverage, findings and owner routes, missing evidence, validation and redaction results, disagreement/supersession log, and TAIL-05/TAIL-06 handoff. Choose and verify exact storage locations through the native plan at activation; no machine-local path belongs in tracked output.

Each finding needs stable ID, severity, repository and exact candidate, path/line or artifact/command reference, observed behavior, impact, affected criterion/interface, reviewer/source-lane provenance, reproduction status, recommended owner, and disposition. Keep product defects, missing proof, review-coverage gaps and packet/tooling faults distinct. TAIL-06 owns corrective integration; #1238 records findings and may repair its own packet defects, but does not silently edit product source.

Before declaring the internal review complete, verify: the touched-repository set is justified, all seven lockset roles and required compatibility edges have exact current identities, every changed role/edge has substantive review and each unchanged role has identity/retained-proof readback; every criterion and historical finding has an explicit disposition; live issue/PR retrieval is complete; all applicable lanes have authored reports and honest examined denominators; each artifact link resolves for its authorized audience and matches its digest; actual installed scenario counts are recorded; raw findings map to the synthesis without loss; public/private projections pass redaction review; independent packet review is current; and native SRP/SOR truth matches the final packet. Missing predecessor acceptance, private material in a public report, or a stale role/manifest blocks a clean verdict. `changes_required` remains a valid truthful review result when this complete review identifies defects.
