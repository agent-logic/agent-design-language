## Findings / blocking ownership decisions

1. **CodeFriend cannot be extracted by moving its directory.** `adl/Cargo.toml:88-91` retains sibling provider-core, UTS, Runtime and kernel dependencies. CodeFriend runner imports provider invocation/communication (`adl/src/codefriend/review/runner.rs:13-14`); architecture generation invokes the adapter too (`architecture/four_plus_one/generation.rs:205-212`). The CLI dispatch resides in mixed `adl/src/cli/mod.rs:193`; `lib.rs:26` exports the product. Decision CF-BOUNDARY: RD02 with CodeFriend/Runtime leads must assign one provider implementation owner and a distributable interface, and separate CLI/build wiring before RD10. Do not copy the provider implementation into both products.

2. **Memory must follow the actual call graph.** CodeFriend-specific palace storage/comparison/baseline consumers belong to CodeFriend (`adl/src/codefriend/memory/`). Palace calls `crate::memory_palace::build_context_from_agent_memory_strict` at `palace.rs:258`. Mixed `adl/src/memory_palace.rs:2-3,135,171` uses observation contracts, kernel types and Runtime service. Decision MEMORY-BOUNDARY: retain shared continuity/services with Runtime, identify portable types separately, keep CF admission/baseline/publication semantics with CF. A filename-based wholesale move loses this boundary.

3. **Website and software are two owners; release assembly currently spans both.** `tools/codefriend_host/release/assemble.py:39-54,75-77` accepts two source revisions, assembles server/verifier binaries, clones the website, and copies host tools out of ADL. `.github/workflows/codefriend-host-candidate.yml:35-43` builds/installs server, agent and ADL from one Cargo manifest. Decision HOST-BOUNDARY: website owns its app/content/site deployment; CodeFriend owns server/agent/report verifier and product service/control contracts; infrastructure owns reusable delivery machinery. Explicitly assign host Terraform, nginx, systemd, idle-stop controller, manifest/assembler and tests individually. These are currently product-specific; do not classify all tools/codefriend_host as generic infrastructure merely because it deploys something. Carry immutable binary and website identities forward into one lockset.

4. **Security enforcement is not synonymous with enterprise policy.** `adl-runtime/src/acip.rs:1-6` explicitly owns the carrier/governance/fail-closed plane. `adl-runtime/src/cav.rs:63,85` requires fail-closed policy/evidence behavior. `adl/src/runtime_v2/security.rs:1-5` is Runtime resume gating. `adl/src/policy_authority.rs`, `csm_credential_policy.rs`, `csm_cav*.rs`, delegation and kernel ACIP need consumer-level classification. Migration plan requires Runtime baseline/default-deny/key/audit interfaces to remain functional without enterprise software. Decision SECURITY-BOUNDARY: RD02/Runtime/security owners distinguish core enforcement, portable schemas, enterprise implementations and retained evidence before RD09. No dedicated enterprise backend ownership or real policy-provider qualification was established by this bounded audit; naming/private placement is not evidence. Preserve no-provider, invalid/unavailable-provider, verified-provider cases downstream.

5. **Infrastructure includes operational tooling outside infra/.** Account/bootstrap/shared modules, runtime service roots and cloud operational docs are visible under infra/ and docs/operations/cloud/. CI, builders and installation are also under `.github/workflows/`, `adl/tools/`, `tools/`. `adl/tools/install_owner_binaries.sh:5-9,158` couples source manifest/provenance and validation runner to ADL. `ci.yaml:558-598` wires CodeFriend reusable workflows and ADL-based acquisition. Decision DELIVERY-BOUNDARY: owning products retain their tests/demos/install contracts; infrastructure consumes pinned artifacts and owns genuinely reusable mechanisms. Cross-repository workflow references, artifact ACL/retention, credential-reference scopes and approval ownership require an explicit map; no actual credentials/cloud state were inspected.
