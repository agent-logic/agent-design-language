  `pr.sh shepherd 4630 --version v0.91.7 --json` reports
  `classification: merged_pending_closeout`,
  `lifecycle_shepherd.state: merged_needs_closeout`, and
  `closeout_required: true`. The same output reports local readiness failed
  because the #4630 source issue prompt is missing from this review worktree:
  `.adl/v0.91.7/bodies/issue-4630-v0-91-7-wp-03-consume-c-sdlc-integration-control-plane-truth.md`.
  The source prompt exists in the root checkout but was not present in this
  review worktree, so the proven defect is the worktree-local repo-native
  command path plus the still-open closeout-state gap, not a globally missing
  canonical prompt.

- P2: The WP-03 remediation packet #4953 fixed the merged-PR/no-PR state split,
  but the current implementation still has no durable "validated closeout
  complete" state for closed issues. This is already tracked by #4950. Until
  #4950 lands, `merged_pending_closeout` is an active shepherd state even for
  issues that may have had manual closeout repair.

- P3: #4780 remains open and cross-cuts WP-03. It is a resilience/workflow issue
  for PR and CI shepherding resilience. It should not block the narrower #4630
  lifecycle-shepherd implementation review, but release-tail docs must not
  imply that all shepherding resilience is complete while #4780 is open.
