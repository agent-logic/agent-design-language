# Provider-neutral lifecycle proof

Issue #855 exercises the installed Runtime generation through the operator CLI and authenticated Runtime API. The local proof uses the genuine OpenAI, Anthropic, Vertex AI, Ollama and OpenAI-compatible adapters against a generated loopback HTTPS fixture. It makes no paid provider calls and does not establish vendor service availability or model quality.

Run `adl/tools/issue855_provider_lifecycle.py` on macOS with Python 3.11+ and `cryptography`. Supply `--csm`, `--csmctl`, `--guardian`, `--kernel`, `--vector`, the build's `--source-revision`, and a new `--output` directory under the issue worktree's ignored `.adl/` directory. Build the binaries from the same source first. The harness never builds implicitly, installs a host service, or removes an earlier run.

The existing generation installer verifies and installs CSM, Guardian and kernel bytes into the isolated output directory. The additional csmctl owner is copied there. Installed CSM validates the configuration against an uninstalled fixture launchd definition through its status command (the expected service state remains unloaded); installed Guardian launches the production kernel directly. A generated local CA retains ordinary hostname and certificate validation. `ADL_PROVIDER_CA_FILE` supplies this CA only to the fixture process; no TLS verification bypass is used. Local SNTP provides host-clock samples, not independent external time authority. Real Vector executes the local observability pipeline.

Each provider row admits a neutral agent and peer through `csmctl agent add`, uses the authenticated Observatory websocket for an operator response and generated canonical agent-to-agent action, writes a checkpoint, migrates, rehydrates, requests a post-restore response, replaces the binding, generates a response on the replacement model, checks the Observatory projection, and removes both agents. The proof compares Runtime PID, incarnation and exact init bytes throughout the five rows. Existing admission greetings are generated behavior and count as inference; constructor validation and metadata health remain separate claims.

The retained report records fixture request paths, models and full generated prompt byte lengths without storing provider credentials. Generated responses and lifecycle/API results are local synthetic evidence. Generation verification and API-level proof are distinct from hosted integration, exact-head review, CI and PR publication. A failed row is retained as failed and must be repaired before the proof can support acceptance.

PVF classification: required runtime/provider integration regression proof; bounded local CPU, disk, process and loopback resources; generated certificates, ports, identities and times vary across runs. Assertions target lifecycle invariants, not byte-identical run artifacts. Hosted provider demonstration and its explicit cost authorization remain separate.

Draft installed execution `installed-run-08` passed all five rows with six generated target requests each, plus one local resident startup request. Each full generated prompt was at most 9,808 bytes; the six prompts totaled 58,496 bytes per provider. These are fixture measurements, not predictions of hosted token billing. The configured input-byte limit applies to each request, while the call limit applies over the process lifetime for that provider definition. A final source-bound proof and independent review must supersede this draft before publication.

## Separately authorized hosted mode

`--hosted-fixture` exercises the hosted topology and its exact request caps with local TLS transports. `--hosted-approved` performs the separately authorized real run; it must not be invoked as an automatic retry. The fixed hosted models are `gpt-5.4-mini`, `claude-haiku-4-5-20251001`, and `gemini-2.5-flash`. The fixed Google project is `cs-host-377d41e71a824f92802120`; a different current project fails before inference. The harness does not change project, billing, IAM or cloud configuration.

Hosted mode uses one hosted agent per vendor and the existing local Beacon as its peer. Same-model replacement changes only the process credential reference to another reference for the same credential. The Runtime definition enforces six calls per provider, 32,000 full prompt bytes per call, 256 output tokens, no transport retries, and refusal after the first failure. The 30-minute process deadline includes teardown: cleanup starts after 1,775 seconds, reserving 20 seconds for graceful termination and five for forced termination/reaping. Cleanup targets only the owned Guardian session and its verified descendant process groups, including the kernel and Vector; an isolated forced-cleanup probe verifies that a SIGTERM-ignoring parent and separately grouped child are killed and the parent is reaped. The approved cost envelope is at most $1 total; measurements report Runtime estimates and request counts, not billed token totals. Local Beacon startup and peer interactions are counted separately and incur no hosted inference charge.

Credentials come from existing `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` or explicit file arguments. Documented fallback files are `$HOME/keys/openai2.key` and `$HOME/keys/claude2.key`; their contents never enter arguments, configuration files, logs or proof packets. A current-project `gcloud auth print-access-token` supplies an ephemeral process-only Vertex token. The harness must run once after the corrected binary and local topology proof are accepted. An uncertain or failed paid run is retained and reconciled before any further operator-authorized attempt.
