# ADR 0084: CodeFriend Beta 1 website and execution boundary

## Status

**Accepted.** Operator decision recorded in Planning #7.3 under #945 on 2026-09-16 (Pacific). Replaces the unaccepted CLI-only proposal for ADR-CF-09; it does not supersede an accepted ADR. Accountable contract owner: CF-SHELL (#891); integration owner: CF-INTEGRATE (#914); independent qualification: CF-PROOF (#915). New implementation work requires bounded owners before integration readiness.

## Decision Question

What product must Beta 1 deliver, and where do reviews run?

## Context

The pinned implementation at `cf7b9d7ff8fc30ec605f994ee70aa838257fca51` contains a local operator shell and individual review consumers. That is incomplete evidence for the product the operator requires. During individual ADR review, the operator required integrated website access, both server-hosted and local execution in Beta 1, and a CLI. The original CLI-only proposal was not accepted.

## Decision

Beta 1 must provide an integrated website supporting both reviews executed on our servers and locally executed reviews controlled through the website. CLI is also supported. Website and private code repositories remain separate; the code repository name remains undecided. Integration and independent qualification must prove both website modes; CLI-only proof is insufficient.

The local mode uses an installed CodeFriend agent connected to the website, with reviews running on the user's computer. Beta 1 website access is invitation-only for both execution modes, with GitHub sign-in. Agent Logic provides and pays for model access for server-hosted Beta 1 reviews. This assigns the product funding model; it does not claim live calls have been made.

Connection protocol, GitHub authentication implementation and hosting topology require their own bounded design and implementation evidence; this decision does not imply they already exist.

The website repository is `agent-logic/codefriend.ai`. Separate private product code supplies the integrated functionality through versioned contracts. Current ADL source placement is pre-extraction state. Repository migration remains the separately reviewed v0.93 work; it must not defer either Beta 1 website mode. No code repository identifier is selected here.

Reuse shared Runtime, provider, evidence and Memory Palace ownership. The website and local agent must preserve evidence identity, privacy, retention, run lifecycle and exact-artifact approval across modes. CLI support does not substitute for either website journey. Autonomous source mutation remains outside this decision.

## Alternatives Considered

A local CLI alone fails the operator's Beta 1 requirement. A server-only website excludes the required local execution mode. Disconnected website and code repositories fail the required integrated product experience. Separate repositories with integrated behavior preserve both the requested ownership boundary and product access. These are the curator's rationale for the recorded direction, not claims of additional stakeholder decisions.

## Consequences

Website access, server execution and installed local-agent control add implementation and operational work. #914 cannot absorb unfinished features and declare integration complete; missing components need explicit implementation owners and accepted outputs first. #915 must independently qualify both modes on the same identified release candidate, alongside CLI support. Authentication, authorization, disconnect/retry semantics and source-data handling must be implemented and tested before access is enabled.

## Reversibility

Changing a supported execution mode requires an explicit product decision and migration for installations, active runs and evidence references. Moving code between repositories alone cannot establish product compatibility.

## Validation Notes

Run the actual invited-user website journey in server mode and installed-agent mode: ingestion, review, synthesis, action plans, approval and rendering, including failed, cancelled and interrupted attempts. Independently qualify the installed product on the selected macOS/Linux and pinned external repository scope. Verify uninvited access rejection, isolation of users' runs and artifacts, and local execution location. CLI-only runs, fixtures and module presence are insufficient. This document records requirements, not successful tests or deployment.

## Approval Boundary

The operator accepted the revised decision summary and separately selected an installed local agent and invitation-only access. The old CLI-only candidate digest is retained as rejected proposal history, not as the approved text. Acceptance does not authorize merge or certify implementation, deployment or release readiness.

## Beta 1 scope clarification

The operator deferred bring-your-own-key (BYOK) until after Beta 1. GitHub sign-in remains the confirmed Beta 1 method; Google sign-in was discussed but not approved. Agent Logic supplies server-hosted model access. The local-agent model-access mechanism remains a required implementation decision; BYOK must not be assumed as its Beta 1 solution. This does not defer either website execution mode.
